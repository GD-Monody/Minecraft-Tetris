# 我的世界俄罗斯方块 3D 版：设计规格 v0.1

2026-10-25 初稿。这一版是给马克杯 2022 年的 TetrisM 做升级：保留 MC 方块外观和方块特性，场地换成真正的 3D 网格。

2026-10-27 修订：补「水 + 岩浆成石」的完整规则（黑曜石 / 原石），MC 方块特性章节按实际实现更新。文件名保留 v0.1。

## 场地

- 3D 网格：x 宽、y 高、z 深
- 默认 10 × 20 × 1，三个轴都在设置里调
- 初版可调范围：x 5~20，y 10~40，z 1~10
- 方块沿 y 轴下落，底部是地板
- 相机绕场地中心轨道旋转，上下左右都能看，滚轮或双指缩放

## 方块

- 每个方块由 4 个立方体组成
- 平面块 7 种：I、O、T、S、Z、J、L。z = 1 时就是原版俄罗斯方块的玩法
- 立体块：z ≥ 2 才进入生成池，形状待定
- 生成用 7-bag 随机（标准和原版一致）
- 移动：左右（x）、前后（z）
- 旋转三套，对应屏幕上三根轴，各两个方向，可以任意叠加：
  - **面内旋转**（绕屏幕法线）：方块贴着玩家那个平面里转，方块始终正对玩家（原版俄罗斯方块的转法）
  - **俯视旋转**（绕竖直轴）：整块转过去朝别的方向。
  - **前后翻**（绕水平轴）：往背面倒 / 往正面翻，方块躺平或竖回来。
    后两种会改变方块在深度方向占的范围，z = 1 的场地转不动，只在 z ≥ 2 时有用
- 三组旋转叠加以后是完整的 24 种朝向（立方体的全部旋转），不再有"转到某个角度就转不动"的死角
- 1 格厚的平面块绕 x 轴翻 90° 时，"1×1 截面"的 I 型看起来形状不变（只有贴图转了方向），这是几何上的必然
- 下落：自动下落、软降、硬降。自动下落的速度可调，倍率范围 (0, 2]，
  1 = 标准（0.8 秒一格）。3D 场地（z > 1）要前后找落点，1 倍速常常来不及，所以这项必须开放
- 落地后有短暂锁定延迟，期间还能移动和旋转

## 消除

两种模式，设置里切换：

1. 行消：某个深度层的某一行（x 方向）填满，这一行消失
2. 层消：某个高度层的整个平面（x × z）填满，这一层消失

消除后上方方块下落补位。

### 沙子下落

- 会掉的方块：沙、红沙、沙砾、可疑的沙、可疑的沙砾、各色混凝土粉末
- 落定后一直往下掉到踩实为止，掉落不扣分、不消耗回合
- 落定发生在方块写进场地之后、满行判定之前——刚落下的沙子可能正好把下面补满，顺序反了会漏消

### 水 + 岩浆成石（2026-10-27 定稿）

**产物规则**（照 MC 原版的方向，用本项目的「份数」模型表达源与流动）：

- 岩浆格**满格**（8/8 份，等于岩浆源）遇到水 → **黑曜石**（obsidian）
- 岩浆格**不满格**（流动岩浆）遇到水 → **原石**（cobblestone）

**判定**：

- 只看**六向相邻**：上、下、左、右、前、后。斜对角不算。
- 谁主动不区分：水往岩浆流、岩浆往水流，只要相邻就反应，变的是**岩浆那一格**。
- **同一格**也算相遇：水方块落进岩浆那格（或反过来）当场结晶，不会出现"后落的那种把先落的覆盖掉"。

**产物是什么**：

- 是固体方块：写进场地网格，会挡住后面的方块和水、能参与满行判定、被消除时照常下落。
- 它自己不会像沙子那样下落。

**水的去向**：

- 参与反应的水**整格被消耗**，不管那格有几份。
- 这条是为了让场地里的水只减不增：否则水会越灌越多，最后把场地填死。

**连锁**：

- 水多的时候会继续往岩浆那边流，能连着把一片岩浆一块块吃掉。
- 先变出来的石头会挡住后面的水，所以"一次全部反应完"不会发生，看起来是逐块结块。

**节奏**：

- 反应和流动共用一个 tick（0.1 秒）。反应在流动之前做，所以刚生成的石头当 tick 就能挡水。
- 一个 tick 内所有相遇的格子都会处理，不排队、不延迟。

**待补**：

- ~~音效~~ 已补：`random.fizz`（水浇灭岩浆的嘶声），从 26.2 资源库提取。

### TNT 引爆（2026-10-28 定稿）

**怎么拿到**：TNT 不进普通随机池，作为「道具」放在特殊池里（每 12 个方块抽一次特殊池，
其中水 30% / 岩浆 20% / TNT 20% / 沙类 30%）。**抽到 TNT 之后，下一块必定是红石块。**

**怎么点着**：TNT 和红石块**六向相接**（上 / 下 / 前 / 后 / 左 / 右，含同格）就点火，和原版一致；
**挨着岩浆**同样会点着（原版也是，岩浆属于火源）。一次落定后全场扫一遍，所以「新放的红石凑上旧 TNT」
和「新放的 TNT 凑上旧红石」都算；岩浆是流体、不占网格，所以流体每次淌动之后还要再扫一遍。

**引信**：2.4 秒（原版 4 秒，这里一局太快）。燃烧期间方块白闪，节奏照原版：
**0.25 秒白 / 0.25 秒原色**（原版 `TntRenderer` 是每 5 tick 换一次贴图），燃烧期间占着格子。

**爆炸**：球形范围，半径 2 格。

- z = 1 的场地上是半径 2 的圆，约 13 格；场地深到 z ≥ 2 才炸出完整的一团。
- 范围内所有方块都炸掉（包括红石块本身），范围内的水 / 岩浆一起吹掉。
- 范围内的其它 TNT 不直接消失，而是被点着（0.18 ~ 0.55 秒短引信），形成**连锁**。
- 炸掉一格得 4 分（清一行是 100 分，炸一圈差不多半行的收益）。
- 弹坑上方的沙子 / 沙砾会立刻塌下来。
- **原版 TNT 炸不掉的方块，这里也炸不掉**：基岩、三种命令方块、黑曜石、哭泣的黑曜石、
  远古残骸、下界合金块、强化深板岩。它们在原版的爆炸抗性是 3600000 / 1200，
  而 TNT 威力只有 4，所以原版也炸不动。
  被保住的格子不计分。空格里的水 / 岩浆照旧被吹掉（原版 TNT 能把水炸开）。
- **结构方块是唯一的例外**：它在原版的抗性也是 3600000，但在这里是被炸掉才有戏的道具
  （TNT 是它的两个触发点之一），所以故意留成炸得掉。

**被消行带走**：燃烧中的 TNT 如果被消行挪了位置 / 消掉，这颗就哑火，不会在原地炸。

**表现**：`random.fuse` 引信声 + `random.explode1~4` 爆炸声、镜头震动、碎块粒子。

### 原木长树叶（2026-10-28 定稿）

原版里原木不长树叶（树是世界生成时整棵出现的），这是本项目的自创规则：**原木落定后在它周围长树叶**。

- **哪些原木**：自然原木（`*_log`）和六面树皮的「木」（`*_wood`）。
  **剥皮原木不长**（树皮都剥了），**菌柄 / 菌核不长**（菌类没有树叶），竹块不长。
- **长什么**：同树种的树叶，橡木 → 橡树树叶，云杉 → 云杉树叶……共 9 种：
  橡树 / 云杉 / 白桦 / 丛林 / 金合欢 / 深色橡树 / 红树 / 樱花 / 苍白橡树。
- **长哪**：木头正上方、同一层的四个侧面（共 5 个候选位），全部是面相邻的格子；
  只长在空格里，有水的格子不长。位置随机，不会总朝同一边。
  斜上方那 8 格不选：它们和原木只隔着一条棱，长出来看着像隔空浮着的（2026-10-29 改）。
- **长几片**：一个原木格长一片，一次落定最多 6 片。
- **果实性**：树叶是普通方块——挡方块、能凑满行、能被消除、跟着存档走；
  不会自己凋落，也不会再长出新树叶。
- **配比**：树叶不进随机材质池，也就是说不会有「一整块树叶」的方块掉下来，它是木头长出来的。

### 基岩不随消除下落（2026-10-28 定稿）

**基岩消除时钉在原地不动，但自己所在的行被消掉时照样消失**——这是本项目的自定义规则
（原版基岩是不可破坏的，消行也不会跟着掉）。

- **怎么表现**：消行 / 层消之后，基岩停在原来的格子上；它上面那一摞方块停在基岩上面，
  不跟着一起往下走。基岩下面那一格会**永久空着**——那一列从此填不满满行，
  这是「钉住」的代价。
- **它自己能被消**：基岩所在的那一行被判定为满行时，基岩跟那一行一起消失。
- **挡东西**：基岩是实心方块，沙子落到它上面会停住，石头落在它上面会叠着。
- **配比**：常驻特殊池，占特殊池的 12%。它掉下来就是一根柱子，纯增难度，
  设置里的「基岩钉住不动」关掉之后它就成一块普通砖，落下来会跟着消除下落。

### 结构方块的记忆与还原（2026-10-28 定稿，范围为整场）

**结构方块落定时把整块场地记下来，被消掉时把整场还原成那一刻的样子，还原完自己消失。**

- **记住什么**：落定瞬间**整块场地**的每一格方块，包括离它很远的构造。
  记的是**绝对坐标**，不记流体（水不写进网格，记不了）。
- **一块只记一条**：一整块方块里可能有 4 格结构方块，它们来自同一次落定，所以只记一条记忆；
  任意一格被消掉就触发一次，不会连着还原四遍。
- **什么时候记**：结构方块落定的瞬间（方块写进网格之后、重力结算之前）。
- **什么时候还原**：它里面任意一格所在的行 / 层被消掉，或者被 TNT 炸掉。
- **还原的过程**：分两段演。
  消失：场上现有的方块**从下往上、一个接一个**消失（每 0.035 秒收掉一格），水一起收走；
  重建：记忆里的方块**从下往上、一个接一个从上面掉下来**（每 0.05 秒落一格，从目标上方 2 格开始落）。
  两段各封顶 3 秒，方块特别多的时候一次处理多格。
- **同时触发多个**会排队，一次还原一个。
- **副作用**：还原是绝对坐标的，不管中间发生了什么，整场都会回到记忆时的样子；
  记完之后才落下来的方块、被消行搬动过的内容，消失阶段一并收掉。
  还原期间玩家还能操作，重建阶段新放下去的东西会留在原地。
- **配比**：常驻特殊池，占特殊池的 10%。
  设置里把「结构方块还原」关掉，它就变成一块普通砖，照样进池、照样能消，只是不再记事。

### 玻璃被压碎（2026-10-28 定稿）

**玻璃放下来不会碎；之后有方块压到它上面才碎，碎完上方的东西接着往下掉。**

- **怎么算压着**：正上方那一格有实心方块，而且那块**比这格玻璃更晚出现**，才算压着。
  只认正上方，斜着压过来不算。
- **先来后到为什么要紧**：玻璃落定那一刻，上方本来可能就有东西（塞进一个悬空方块底下、
  或者叠在一块旧玻璃上）。按「上方有东西就碎」的老规则，玻璃一落定就自己把自己判成被压着，
  当场碎掉一片，玩家看到的就是「玻璃是易碎品，掉下来就碎」。现在玻璃只被**后来**落上来的方块压碎。
- **玻璃压玻璃不算压**：不然一次落四格玻璃、或者两块玻璃叠着落，下面那块立刻被上面那块压碎，
  看着还是「落下就碎」。
- **碎了怎么处理**：玻璃那一格清空，发一次「压碎」事件给视图层（音效 `break_glass`、碎块粒子、轻微抖屏），
  然后跑一次重力结算：会掉的东西（沙、沙砾、混凝土粉末）落到下一层，
  如果下面还有玻璃，下一轮接着碎，所以叠着几层玻璃会一层层塌下去。
- **什么时候判**：每次方块落定之后，在「重力结算」之后、「判满行」之前扫一遍场地。
  放在判满行之前，是因为玻璃碎了沙会接着掉，掉下来的东西可能正好补满一行，晚一步判就得多等一块。
- **不写进每条落地路径**：落定、重力、行消下移、层消下移、结构方块还原，来源太多；
  默认场地 10×20×1 只有 200 格，整场扫一遍比维护五处判定划算。先后关系由 `Grid` 每格的写入序号提供，
  扫描时比一下大小就行，不用在每条路径上另外维护状态。
- **怎么拿到**：玻璃从普通池里拿出来单独发，大约每 40 个方块里给一块（`BlockPools.GlassEvery`）。
  以前它混在三百多种的普通池里，一等就是几百块，玩家基本见不到它，也就听不到压碎的动静。
  设置里的「玻璃被压碎」关掉之后，玻璃就只是一块普通透明砖。

### 雪与冰遇岩浆融化（2026-10-29 定稿）

**雪块和冰，任意一面贴着岩浆就化成一格水。**

- **怎么算贴着**：六向相邻（上、下、左、右、前、后）任一格有岩浆就算，斜对角不算，和原版一致。
  岩浆不分满格还是流动的薄层，那格只要有岩浆（份数 > 0）就算。
- **化成什么**：那一格清空，原地放一整格水（8 份），于是水会从原来雪块 / 冰块的位置往下淌。
  雪块和冰块本身是整格方块，所以给的是一整格水，不是薄薄一层。
- **接着会发生什么**：水往下淌进岩浆所在的那一格，下一次流体推进就结晶成**黑曜石**
  （源岩浆遇水变黑曜石），于是「雪块压着一汪岩浆」最终留下的是一格黑曜石。
- **只在贴着岩浆时化**：水淌到雪块旁边不化它，水淋下来也不化 —— 只有岩浆算热源。
- **怎么拿到**：雪块和冰都不进普通池，按块数定期发（每 30 块给一块，两者随机各半，
  `BlockPools.MeltEvery`）。理由同玻璃：普通池三百多种，抽中一次要等几百块，
  而这机制的触发条件本来就窄（还得碰上岩浆），埋在池子里等于没有。
- 设置里的「雪与冰遇岩浆融化」关掉之后，雪块和冰就只是普通砖，贴着岩浆也不化。

### 傀儡召唤（2026-10-29 定稿）

**南瓜头压在雪块 / 铁块 / 铜块上，就召出对应的雪傀儡 / 铁傀儡 / 铜傀儡。**

- **怎么算压着**：南瓜头**正下方**那一格是这三种方块之一。只看正下方，斜着压过去、垫两层都不算。
- **两种南瓜都认**：雕刻南瓜（`carved_pumpkin`）和普通南瓜（`pumpkin`），原版两个都能召唤。
- **召唤要付代价**：南瓜头和脚下那格**一起消失**。傀儡是由这两格「变成」的，不是白送的；
  抽走两格之后上面压着的东西会塌下来，可能正好补满一行。
- **傀儡去哪了**：不在场地里活动，而是挪到**场地右侧**摆成一排当收藏（最多 8 个，三列两行）。
  场地里只少掉那两格，碰撞、消行、重力一条规则都没变。
- **长什么样**：全部用方块拼，和场地里的方块同一套材质 ——
  雪傀儡 = 两格雪 + 南瓜头；铁傀儡 = 两格腿 + 一格身体 + 两侧各一格手臂 + 南瓜头；
  铜傀儡 = 一格身体 + 两侧手臂 + 南瓜头（比铁傀儡矮一号，和原版的比例一致）。
- **一局一清**：新开一局时场地外的傀儡一起清掉，收藏不跨局。
- 设置里的「傀儡召唤」关掉之后，南瓜头压在什么上面都只是一块普通砖。

### 着火与蔓延（2026-10-30 定稿）

**木头、羊毛、树叶挨着岩浆就被点着，烧一阵子烧没了，火还会往旁边传。**

- **什么烧得着**：木头（原木 / 木板 / 去皮木头 / 木制品）、羊毛、树叶，按方块名特征词判定
  （354 种里命中 82 种）；铁门、末影箱这种名字里带 door / chest 的单独排除，
  下界的绯红 / 诡异木原版本就抗火，也排除。
- **怎么点着**：可燃方块**六向相邻**有岩浆就算（岩浆是流体不写网格，查流体层的份数），
  斜对角不算。方块落定时扫一遍，岩浆淌动之后再扫一遍。
- **烧多久**：每块随机 2.2 ~ 4.4 秒。原版一块木头烧 30 ~ 90 秒，一局俄罗斯方块里那样太慢。
  烧完那一格直接空掉，上面压着的照常塌下来，得 2 分一格（TNT 是 4 分：火慢、也不挑位置）。
- **怎么蔓延**：每 0.45 秒往随机一个方向传一格火，只传六向里的可燃邻居，一次只传一格。
  不掷「这轮传不传」的骰子 —— 连着几轮没中的话火看着像卡住了。
- **水能灭火**：旁边有水的方块点不着，已经烧着的水漫过来就浇灭，方块本身留着（原版同款）。
- **长什么样**：火不是一个方块（原版火占一格），只是方块身上的状态 —— 好处是坐标不会
  跟着重力 / 消行错位（TNT 引信也是这么处理的）。燃烧的格子照原版模型铺火苗面片：
  解包原版 26.2 的 fire_0 / fire_1 贴图（16x512 各 32 帧，拼成一张 32 帧动画条），
  长在这一格露在外面的面上，侧面火苗比方块高一截（原版侧面火苗就是 22.4/16 高）。
- 设置里的「木头羊毛树叶会着火」关掉之后：点不着，烧着的直接掐灭，方块照常进池。

### 海绵吸水（2026-10-30 定稿）

**干海绵把周围一圈的水吸进肚子，自己变成湿海绵；湿海绵就吸不动了。**

- **吸水范围**：以海绵为中心的 7×7×7（切比雪夫半径 3），从海绵向外逐格找水，一次最多吸
  **65 格**（原版同款数字）。实心方块挡路，隔墙的水吸不到。
- **半格水也算**：流动中的薄水照样吸走；被吸干的格子空出来，水不会再来（除非别处流过来）。
- **湿与干**：一格都没吸到的海绵保持干燥，下次还能接着吸；吸到了（哪怕一格）就变湿。
  这里没有熔炉，湿海绵就一直是湿的，也不会自己变干。
- **分数**：吸一格水得 1 分 —— 排水能帮层消腾地方，但不毁方块，比火的 2 分还低。
- **触发时机**：海绵落定时扫一遍，水淌动之后再扫一遍。
- 设置里的「海绵吸水」关掉之后：海绵就只是一块普通黄砖，泡在水里也不吸。

### 之前想留的接口方案（已废弃）
原计划定义 `IBlockEffect` 加四个空实现，把效果做成可插拔的。实际做的时候发现效果和主循环耦合很紧（沙子必须在写网格之后、判满行之前跑；流体要和 Grid 双向通信），套一层接口只是多绕一圈，最后写成 `Gravity` 和 `Fluids` 两个静态类，直接在 `GameLoop.LockPiece` / `Tick` 里调用。`Assets/Scripts/Effects/` 目录留着没删，将来 TNT 那种独立性强的效果可以还做成组件挂进去。

## 操作（PC）

- A / D 或 ← / →：左右移动
- W / S 或 ↑ / ↓：前后移动（z 轴）
- 空格：硬降
- Shift：软降
- Q / E：面内旋转（逆 / 顺时针，绕屏幕法线）
- Z / C：俯视旋转（逆 / 顺时针，绕竖直轴）
- V / R：前后翻（往正面 / 往背面，绕水平轴）
- 鼠标拖拽：转视角
- 滚轮：缩放
- Esc：暂停
- 设置里可以自定义键位，改完立即生效

手机后续做屏幕虚拟键加拖拽转视角。

## 界面

- 主界面：开始、设置、退出
- 游戏界面：场地、下一块预览、分数、等级、暂停
- 设置：场地尺寸（三个轴）、消除模式、下落速度、音乐音量、落点提示、键位、音效、特殊方块机制开关
- 场地尺寸（x / y / z）、下落速度、音乐音量都用 MC 那种拖拽滑条（整条轨 + 圆头，拖或点都行），
  数值直接写在滑条上；尺寸是整数刻度，拖的时候自动取整。其余选项是按钮
- **深度 Z = 1 时消除模式固定为行消**：一层就是一行，层消在这里没有意义，按钮置灰并标「Z=1 固定」。
  深度调回大于 1 之后才能切层消（存档里也不会残留一个「层消」等着跳出来）

### 视觉风格

- **字体：华文楷体**（2026-10-29 从方正字迹-龙吟体换过来）。界面上的中文全是这个字体，包括标题、按钮、HUD 文字、
  方块名。英文 / 数字也走同一套字形，保证风格统一
- **字号整体放大到 1.25 倍**，由 `UiSkin.TextScale` 一个常量控制，布局尺寸一起等比放大。
- **设置类页面（主页 / 按键 / 场地尺寸 / 下落速度 / 音量 / 机制开关 / 游戏规则）再放大一倍**：
  页内尺寸过 `TitleScreen.Pg()`、字号过 `Fg()`，同一个 `PageScale = 2` 系数，等比长大不会错位。
  放大后一列放不下的页面改成两列（按键 6+6、机制 5+5、规则玩法 3+3、特殊方块 4+4+3）。
  默认窗口 1440×900 下最大的面板（按键设置）高 838px，塞得进去；想再放大记得同步检查这一条
- **主菜单按钮再单独放大**，目标是当下的 2 倍（`UiSkin.MenuScale = 2f`）。屏幕装不下时自动降一档：
  1440×900 五个按钮实到 1.53 倍（535×84，字号 34），六个按钮 1.27 倍；1920×1080 五个按钮约 1.98 倍。
  按钮上的字跟着按钮一起长，不会出现「框大了字没大」
- 底部署名文案是「AGENTS辅助完成」
- **主菜单带一页「游戏规则」**（`游戏规则` 按钮）：面板顶上一排三颗，玩法 / 按键 / 特殊方块，
  点哪颗看哪栏，面板尺寸不跟着换。
  - 玩法：六段小标题加正文，讲目标、摆法、场地、三套旋转、特殊方块、分数与创意工坊。
  - 按键：读当前键位，两列各六行，左列操作名右列键名；底部两行提示改键去哪里、深度不够时哪些旋转用不上。
  - 特殊方块：两列十一行，每行一个图集图标、方块名和一句机制说明，覆盖 TNT、红石块、结构方块、
    基岩、黑曜石 / 哭泣的黑曜石、防爆方块、水、岩浆、沙子 / 沙砾、玻璃、原木。
  写这一页是因为给没玩过 MC 的朋友玩时，玩法和这些机制不看说明根本猜不到
- **设置里带一页「特殊方块机制」开关**（设置 → 特殊方块开关）：十四项各一个开 / 关按钮，
  TNT 爆炸、接触点火、沙子与沙砾下落、原木长树叶、水会流动、岩浆会流动、结构方块还原、
  基岩钉住不动、防爆方块炸不掉、玻璃被压碎、雪与冰遇岩浆融化、傀儡召唤、
  木头羊毛树叶会着火、海绵吸水。
  关掉的含义是「这种方块不再按特殊规则动」，方块本身照常进池；开关存在 PlayerPrefs，改完立即生效，
  不清存档也不重建池
- **光标带深蓝色荧光拖尾**：尾部长约 0.28 秒，靠近光标是亮蓝白的内芯，越往后越散越淡；
  光标本身有一圈缓慢呼吸的外光晕
- 配色沿用 MC 风深色半透明面板 + 灰白细边框，强调色是草绿 `#85C74C`

## 音频

- **背景音乐**：MC 原版的 14 首常速曲（Sweden / Minecraft / calm1~3 / hal1~3 / Haggstrom /
  piano1~3 / nuance1~2）+ 2 首菜单曲（menu1 / moog_city_2），从本机正版资源里提取，

  开头淡入、结尾淡出。标题界面用菜单曲库，进游戏换成常速曲库，切界面时淡出当前这首

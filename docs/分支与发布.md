# 分支与发布

一套 Unity 工程同时出三个东西：Windows、网页（WebGL）、安卓（APK）。
三边的差异主要是**构建参数和运行时判定**（`MobileMode`），代码本身是同一份，
所以不按平台拆代码，只按「发到哪个端的哪一版」拆分支。

## 分支

| 分支 | 作用 |
|---|---|
| `main` | 唯一开发主线（默认分支）。所有共享改动都提在这里 |
| `web` | 网页发布快照。指向「线上那个 WebGL 包」对应的提交 |
| `android` | 安卓发布快照。指向「最新那个 APK」对应的提交 |

发布分支只用来回答一个问题：**线上跑的是哪份代码**。
它们不承接日常开发，避免出现「网页分支和安卓分支各改各的、最后合不上」。

## 日常怎么走

1. 新功能 / 修 bug 一律提到 `main`（仍然是一个逻辑一个提交，与平台无关）。
2. 平台专属的改动直接提在对应发布分支上，并同步回 `main`：
   - 安卓专属：构建脚本、`PlayerSettings` 的安卓项、只影响手机的调参；
   - 网页专属：`Assets/WebGLTemplates/`、发布目录里的模板页。
   这类改动照例在提交正文里写清「只影响哪一端」。
3. 要发布某一端了：把 `main` 合进对应发布分支，构建，打 tag。

## 标签

每次真正发布打一个 `release/<端>-<日期>` 标签，指到当时构建用的那个提交：

```
release/web-2026-11-24     网页版，工坊文案那版（BuildWebGL 19:43 构建 / 19:50 发布）
release/apk-2026-11-25     安卓包，IL2CPP+ARM64、旋转定长缓动、帧率跟随刷新率
```

要看「线上是什么」就 `git show <tag>`，比翻提交历史快。

## 当前的已知差异

`main` 和 `android` 现在指向同一个提交（分叉从这次开始）。
`web` 落后 5 个提交，差的都是手机专属或调试用的东西：

- 旋转的定长缓动（**网页可见**，线上还是旧的逐帧追目标）
- 目标帧率跟随屏幕刷新率（只在 `MobileMode.Enabled` 时生效，桌面浏览器进不去）
- 帧率角标 / 分段计时（默认不显示，`-fps` 才开）

下次网页发布时，把 `main` 合进 `web` 即可，旋转手感会随之一致。
